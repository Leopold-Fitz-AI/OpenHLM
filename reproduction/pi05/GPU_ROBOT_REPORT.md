# pi05 GPU 与 G1 仿真评估结果

已完成 GPU 推理、两步 GPU 训练及训练产物重新加载，并完成原始 G1 控制链的仿真评估。
本报告的机器人结果限于空地场景下的单次有效基线和单次有效 VLA 试验，不能推导任务成功率。

## GPU 验证

| 项目 | 结果 |
|---|---|
| GPU | A100-SXM4-80GB；GPU 3 推理，GPU 4 训练及之后的底层控制 |
| 模型 | 官方 `12tasks_12full-teleop`，π0.5，50×34 动作 |

| 预热后直接推理 | 10 次平均 322.17ms，P50 320.45ms，P95 331.84ms |

| GPU 训练 | 从 π0.5 基础模型开始；batch=2，2 步，梯度检查点开启 |

两步训练只验证训练路径，不证明收敛。机器人试验使用官方完整微调权重，而非这个两步 checkpoint。

## 最终机器人试验

链路为：官方 OpenHLM → 原始 `SonicG1Env` → ZMQ → 原始 C++ SONIC/TensorRT 控制器
→ Unitree DDS → MuJoCo G1。高层使用项目默认的同步请求和 25 帧开环执行方式。
底层线程配置为 Input 100Hz、Control 50Hz、Command Writer 500Hz；没有修改控制策略。

两组使用相同起步条件：虚拟支撑在 2 秒内从 1.0m 降至 0.78m，撤除支撑后等待 3 秒，
检查高度至少 0.6m、机身倾斜不超过 0.4rad，再开始 20 秒试验。

| 指标 | 默认姿态基线 | 官方 VLA |
|---|---:|---:|
| 评估墙钟时长 | 20.007s | 20.037s |
| 动作步数 | 599 | 426 |
| 客户端实际更新频率 | 29.94Hz | 21.26Hz |
| 策略请求数 | 0 | 18 |
| 跌倒 | 无 | 无 |
| 评估期间最低基座高度 | 0.7785m | 0.7788m |
| 状态数值 | 有限 | 有限 |

VLA 请求平均 352.86ms、P95 387.74ms，包含本机 WebSocket 往返及策略执行。
底层日志中，33 次周期采样的 SONIC policy 推理平均约 95.06μs、最大 104μs；
这是单个底层策略推理耗时，不是完整控制周期。

实际更新频率低于设定的 30Hz，符合当前同步架构：每次等待新动作块时，高层不继续发送新参考。
底层控制线程独立运行，不能将高层阻塞理解成电机命令线程停止。

离屏渲染使仿真实时因子约为 0.91；20 秒墙钟评估对应约 18.2 秒物理仿真时间。
因此这些结果不证明严格实时性能。

最终数据：

- `results/g1_sim_baseline_grounded/`：基线指标、原始遥测。
- `results/g1_sim_vla_grounded/`：VLA 指标、原始遥测、视频和预览。
- `results/gpu_robot_summary.json`：机器可读汇总。
- 服务器完整日志在 `/mlplatform/OpenHLM-repro/logs/` 下对应同名目录。

为了不把调试或无效起步混入正式结果，保留了以下记录：

| 服务器日志目录 | 状态与处理 |

| `g1_sim_baseline_grounded`、`g1_sim_vla_grounded` | 浮点支撑坐标、平稳落地、清晰相机视野，采用本报告最终结果 |

这些试验不是固定协议下的一组独立任务测试，不能把它们合并计算成功率。

## 范围限制

- 场景只有机器人和地面，没有瓶子、垃圾桶、抓取目标或任务完成判据。
- 新增腕部相机为近似挂载，未进行真实相机内外参标定；头部使用项目原有模拟相机。
- MuJoCo 模型使用 Dex3 手；论文中的 CTAG 夹爪状态在当前桥中以张开值表示，未验证抓取。
- DDS 仅使用 `lo`，ZMQ 仅绑定回环地址，没有连接或控制实际 G1 机器人。
- 完整任务评估还需要匹配硬件的机器人模型、对象与任务场景、重置条件和成功判据。

并优先使用系统 GoogleTest。最终 C++ 构建通过；没有修改 VLA 或底层策略的实现和权重。
