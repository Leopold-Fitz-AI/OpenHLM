# 官方 VLA 观测与动作一致性排查

> 后续相机/TCP、空抓与碰瓶排查见 [TCP_ALIGNMENT_REPORT.md](TCP_ALIGNMENT_REPORT.md)。

## 结论与证据范围

官方权重能在公开示范输入上预测闭合、持瓶、松手。当前合成场景中长期张开，
不能归因于模型只会输出“张开”，或把闭爪值解释反了。受控图像/状态交叉替换表明，
抓取前的视觉输入差异足以改变夹爪预测。已修复发现的软件和评估时序偏差，
但相机标定、CTAG 机械模型和真实场景外观尚未严格复刻；任务结果以本页实测为准。

## 权重和训练接口

- 权重：`OpenHLM/OpenHLM-ckpts` 的 `12tasks_12full-teleop`，revision `f3a109f817c65ea76a659d0b7b6f7cfff6d6825c`。
- 检查点元数据：π0.5、34 维动作、50 帧预测、离散状态 token、绝对关节动作，
  `use_delta_joint_actions=false`、`use_first_action_delta=false`，与 `openhlm_example` 一致。
  元数据通过 ZIP/pickle 指令静态读取，没有执行不可信 pickle。
- 归一化：使用检查点自带 `assets/OpenHLM/example/norm_stats.json` 的 quantile，
  没有用本地演示重新算出的统计量替换。夹爪动作 q01=0、q99=1。
- 训练转换器、采集端、Python 客户端和 C++ ZMQ 输出逐项核对：
  左臂7、左夹爪1、右臂7、右夹爪1、左腿6、右腿6、腰3、根姿态/转向速度3。
  根部前三项是 roll、pitch、yaw velocity；不是绝对 yaw。
- C++ 返回的身体状态已经恢复为真实机器人关节顺序和绝对角度；不能再次添加默认角偏置。
- 动作发往 IsaacLab 的 29 维重排与 C++ 逆映射一致，没有发现左右手或肘关节错位。
  0 表示闭合、1 表示张开；仿真夹爪反馈来自实际滑动关节，不回填命令。

## 官方示范回放与交叉实验

公开数据源为 `Yingdong-Hu/g1_twelve_tasks` 示例包，revision
`fe7f13138d0a22a2a2b06b775e4effef9eb54903`；使用 `20260520_1602_example_1/episode_0000`。
视频按 data.json 引用的 frame_index 解码，OpenCV BGR→RGB 一次，保持宽高比补黑边至224。
文字指令始终为 `Walk towards the platform and put the green bottle into the dust bin.`。

直接调用原始 Policy.infer，固定随机噪声 seed=42、50×34、10步去噪，逐项只替换图像或状态。
这里是训练接口的点检，不是保留测试集成功率；公开示范可能属于训练分布。

| 输入 | 右夹爪前25帧平均值 | 含义 |
|---|---:|---|
| 真实示范第0帧 | 0.999 | 初始张开 |
| 真实示范第380帧 | 0.139 | 接近首次闭爪，开始预测闭合 |
| 第380帧真实图像 + 原仿真初始状态 | 0.022 | 保留仿真状态也能预测闭合 |
| 原仿真图像 + 第380帧真实状态 | 1.000 | 换成仿真图像后保持张开 |
| 真实示范第400帧 | 0.016 | 正在抓取，目标动作0 |
| 真实示范第600帧 | 0.010 | 持瓶，目标动作0 |
| 真实示范第1300帧 | 1.003 | 已松开，目标动作1 |
| 原仿真初始输入 | 1.001 | 一直张开的现象可重现 |

输出略超出[0,1]来自连续策略，物理夹爪执行时限幅。原始14组结果见
`results/observation_audit/replay.json`。第400帧真实输入首动作34维 MAE约0.074。
这个对照支持“视觉分布是重要因素”，不证明视觉是唯一根因。

## 发现与修复

1. **图像几何不同。** 公开头部视频400×464、腕部480×640，训练转换后分别有上下黑边。
   原仿真直接发224正方形，缺少这些比例和黑边。现在分别渲染200×232、240×320，
   等比例缩小原始分辨率；客户端用训练一致的 PIL bilinear + resize_with_pad 得到224图像。
   确认三路 BGR→RGB 一次，左右腕拆分正确，没有重复拉伸。
2. **头部投影不同。** 公开示范明显为圆形鱼眼，原仿真是100°针孔。
   新增五面立方体投影生成的近似180°等距鱼眼，保留相同机器人相机刚性挂载。
   镜头系数、光心和外参没有官方标定文件，180°是近似值，不能称为精确标定。
3. **腕部视野与遮挡。** 原始近似挂载视线接近水平；调整向下视角，并把镜头移到夹爪底座前方，
   减少底座遮挡。该位置针对物理替代夹爪，不代表真实 CTAG 标定。
4. **转向速度计算错误。** 原客户端用固定1/30秒差分。同步推理停顿约0.3秒时，
   会把整个间隔的转角当成一帧；原仿真初始观测曾出现-1.219rad/s。
   已复用采集端 `QuatProcessor`：实际 monotonic_ns 时间差、角度环绕、EMA α=0.1、±2rad/s限幅。
5. **控制频率不足。** 原同步25帧执行期间推理会阻塞，实际约21.9Hz。
   增加异步预取：第12个控制tick发起下一次请求，第25个tick更新动作块，
   丢弃从采样到执行已经过期的预测帧。继续使用原始50帧模型输出和原始 SONIC 控制器。
   这不是训练过的 RTC；每次捕获/应用tick与跳过帧数保存在 `replans.json`。
6. **仿真时钟变慢。** 原逐循环推进一次物理，渲染开销使仿真115.48秒对应墙钟126.38秒。
   现按累计时间补齐200Hz物理步；一次修复后复测126.530/126.535秒，基本实时。
   最终将物理步进放在独立线程，相机使用独立 MuJoCo 模型/数据快照，避免渲染阻塞控制或改变求解器状态。
   超过0.1秒物理积压会终止，不能静默继续失真的评估。
7. **流是否过期不可见。** 现在记录身体、夹爪、头部及双腕的接收年龄，任一路超过0.5秒即终止。
   这些是接收端时间，不能证明相机曝光与关节采样严格同步。头/腕协议没有源采集时间戳。

没有更换官方权重、反转夹爪或插入脚本抓取。模型只接收相机、关节/夹爪测量和文字。
瓶子位置、任务判据和全状态遥测不进入 VLA。

## 复测与验证

回归测试：`test_observation_mapping.py` 7项通过（状态顺序、三路颜色/左右拆分、
延迟时 yaw 差分、采集端滤波、角度环绕/限幅、动作顺序、完整29关节重排、缺失/过期流）；
既有 `test_task_metrics.py` 7项继续通过。任务成功仍要求双指接触、抬升和松手后稳定入桶。

初步对照：修复宽高比和yaw后90秒，1974动作步、21.927Hz，仍未抓取；
加入近似鱼眼和异步执行后90秒，2684步、29.822Hz，仍未抓取。
再对齐物理时间、增加相机更新目标和向下腕部视角的90秒测试仍未抓取，控制29.822Hz。
该次流最大接收年龄：身体0.00042s、夹爪0.0677s、头0.0904s、腕0.0894s。
这些试验改变项不同，用于定位问题，不混算为同协议成功率。

最终配置第一轮已出现右夹爪闭合（最小命令0）、约3.086N指尖接触力和4.536N总工具接触力，
但双指接触未持续成立，瓶子被碰离平台，未完成抓取、抬升或投放。
相机更新目标30Hz，第一轮实际21.72Hz；这是尚未完全匹配采集频率的限制，不能把目标频率当实测值。

最终同配置三次90秒复测：**持续抓取0/3、抬升0/3、稳定投放0/3**；三次均未跌倒。
三次均出现闭爪，第一轮接触并碰走瓶子，另外两轮未记录到瓶子接触。

## 仍缺失的训练一致性条件

真实相机内外参/畸变标定、完整 CTAG 几何/开度标定、与训练一致的场景外观和物体资产，
以及采集时间戳同步都尚未获得。公开示范的右手持瓶反馈约0.563，而仿真反馈由替代夹爪
实际间距归一化，不能假设相同数值就代表相同物理宽度。
当前官方模型在合成域的零样本抓取能力尚未得到验证。软件错误已修复不等于完整任务成功。
